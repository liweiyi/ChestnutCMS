# ChestnutCMS 内容分发模块首期方案

评审稿 · 2026-11-19

在 `chestnut-cms/chestnut-cms-distribution` 建立独立的内容分发模块。首期支持编辑从 CMS 视频集中选一条视频投到抖音，从 CMS 文章生成图文稿投到今日头条。建议从**编辑手动选择已发布内容、预览并确认目标账号**开始。站内发布继续由 CMS 负责，站外每个账号拥有独立的投稿记录和结果。

## 编辑怎样使用

1. 站点管理员在「内容分发 → 平台账号」绑定可通过 API 投稿的账号，或登记人工投稿所用的头条号。页面显示平台、账号名、所属站点、投稿方式和授权状态。一个站点可以使用多个同平台账号。
2. 编辑在内容列表打开一条已发布稿件的「分发」操作。视频集显示可选片单和封面，文章显示转成平台格式后的标题、正文、封面和配图。页面按内容类型列出匹配的平台及本站可使用的账号，缺少权限或材料时说明具体原因。
3. 编辑核对稿件、可见范围和一个或多个目标账号后确认。一次确认针对一条稿件或一段视频。需要更改原文或替换视频时，回 CMS 编辑并重新发布，再生成新预览。
4. 编辑在「分发记录」按内容、平台、账号、时间或状态查看结果。同一次投给两个账号，可以分别看到一个已公开、另一个审核中。详情保留实际提交的稿件、操作者、平台回执和后续动作。

首期建议支持本站公开、可对外传播、具有独立正文或源文件的稿件。跳转链接、只有源稿引用的映射稿、限制访客阅读的内容在预检中说明原因。CMS 发布过一篇文章或重新生成静态页，都不会自行向外投稿。后续如启用按栏目自动分发，应单独配置目标账号，并以各平台允许的授权方式为前提。

## 首期平台能力

| 目标 | 投稿方式 | 上线验收条件 |
| --- | --- | --- |
| 视频 → 抖音 | 以已授权用户身份上传视频，取得素材标识后创建作品，保存平台作品标识。预览按实际权限展示描述、封面和可见性选项。 | 目标应用获批代用户发布能力，目标账号授权。用该账号完成一次真实投稿，并核对作品及其可见状态。 |
| 文章 → 今日头条 | 目标为头条号图文投稿。优先验证官方 API 接入资格，等待期间可交付人工投稿流程。 | API 验收须取得该主体适用的官方文档和授权，验证账号绑定、图文投稿及真实回执。若只获批草稿能力，显示「草稿已创建」。 |

**抖音。** 上传与创建作品都需要应用获批 `video.create.bind`（能力实验室的「代替用户发布内容到抖音」）并取得目标用户授权。按官方规则，视频大于 300 MB 必须分片上传，总大小在 4 GB 以内，时长不超过 15 分钟。取得素材标识 `data.video.video_id` 后，以该用户的 `open_id` 和用户令牌创建作品。检查业务错误码，成功后保存作品标识 `data.item_id`。审核期间作品仅自己可见，创建回执只足以标记「平台已受理」。[抖音开放平台 · 上传视频](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-video/upload-video) · [创建视频](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-video/video-create)

**头条。** 已确认头条号创作后台入口，第三方通过服务端代发文章的适用资质、接口及授权范围仍需头条侧确认。建议用拟上线的主体申请，取得相应文档后验证图片规则及审核结果查询方式。等待准入期间，编辑可复制排版稿、下载封面和配图，在头条号后台发文，再回填作品链接。记录标明「人工投稿」及核对人。此时 API 投稿入口显示「待平台开通」，人工记录单独验收。[头条号创作后台](https://mp.toutiao.com/)

后续视频平台按哔哩哔哩、快手、小红书等各自获准的投稿方式接入。微信公众号（含订阅号）按目标账号可用的素材、草稿、发布能力接入。平台只支持唤起客户端确认、创建草稿或人工发布时，界面应显示实际需要完成的动作。账号授权情况决定可用操作。

## 模块如何接入项目

| 职责 | 建议落点 |
| --- | --- |
| 内容与素材读取 | 分发模块单向依赖 `chestnut-cms-contentcore`、`chestnut-cms-media`、`chestnut-cms-article`。按 `video`、`article` 选择素材提取器，通过现有服务取得内容、视频条目、正文和资源流。 |
| 分发流程 | 分发服务负责预检、生成预览、保存编辑确认的快照、派发任务和记录结果。平台以 Spring Bean 实现 `DistributionPlatform`，声明平台标识、内容类型、所需授权、支持的选项和结果核对方式，封装授权、素材上传和投稿协议。 |
| 管理端 | 在内容列表的列表、表格视图共用一个「分发」操作。新增「平台账号」「分发记录」两页。后台提供账号授权与解绑、可用目标、预览、确认提交、人工投稿取稿及回填、记录及结果核对接口。平台选项由后端能力和账号授权共同决定。 |
| 装配与存储 | 实施时加入 CMS 父 POM、根 POM 的依赖管理和 `chestnut-admin` 装配。菜单、权限和业务表随 Flyway 提供 MySQL、PostgreSQL、Kingbase、达梦脚本，管理端沿用现有国际化机制。 |

当前 CMS 在发布事务内触发 `AfterContentPublishEvent`，对已发布内容重发也会触发。手动分发以编辑确认作为唯一的建单入口。后台可以复用 `AsyncTaskManager` 执行上传，页面刷新或任务进度过期后，从数据库读取分发历史。[CMS 发布逻辑](../chestnut-cms-contentcore/src/main/java/com/chestnut/contentcore/core/AbstractContent.java) · [发布事务](../chestnut-cms-contentcore/src/main/java/com/chestnut/contentcore/service/impl/PublishServiceImpl.java) · [异步执行器](../../chestnut-common/chestnut-common-core/src/main/java/com/chestnut/common/async/AsyncTaskManager.java)

### 从 CMS 稿件得到投稿素材

- **视频。** 用 `IVideoService.getAlbumVideoList(contentId)` 读取视频集，按 `sortFlag` 排序。只有一条可分发视频时可预选，有多条时由编辑指定 `videoId`。将所选条目的标题、描述、封面和源文件带入预览，校验条目属于当前内容。通过 `IResourceService.readResource` 读取本站托管的本地或对象存储资源，按平台要求检查格式、大小和时长。`type=SHARE` 存储的是第三方嵌入代码，提示编辑补充源文件。[视频模型](../chestnut-cms-media/src/main/java/com/chestnut/media/domain/CmsVideo.java) · [视频服务](../chestnut-cms-media/src/main/java/com/chestnut/media/service/IVideoService.java) · [资源读取](../chestnut-cms-contentcore/src/main/java/com/chestnut/contentcore/service/IResourceService.java)
- **文章。** 基础字段取自 `CmsContent`，正文取自 `CmsArticleDetail.contentHtml`。首期覆盖 `RichText`，按阅读顺序合并分页，保留标题、段落、可用的图片和署名。识别站内资源后再做平台转换，以允许的标签清洗正文，将配图转换为目标平台接受的素材标识或公开地址。预览指出无法转换的组件、外链素材及必填字段，阻止提交缺图或残留模板标记的稿件。Markdown 可在其正文格式处理器接入并验证后开放。[文章模型](../chestnut-cms-article/src/main/java/com/chestnut/article/domain/CmsArticleDetail.java) · [富文本处理器](../chestnut-cms-article/src/main/java/com/chestnut/article/format/ArticleBodyFormat_RichText.java)

### 账号、权限与任务数据

| 建议表 | 记录内容与约束 |
| --- | --- |
| `cms_distribution_account` | 站点、平台、平台账号标识、展示名及启停状态。API 绑定另存应用配置引用、授权范围、到期时间和加密凭据。同站点、同平台、同应用、同平台账号唯一，重新授权更新原绑定。仅供人工投稿的账号由管理员登记并标明「人工」，无需 API 凭据。 |
| `cms_distribution_task` | 一个目标账号一条任务。保存确认批次、站点、栏目、内容、所选视频、账号、投稿方式、不可变稿件快照、资源 ID 与文件标识、操作者、时间、当前状态、平台稿件 ID 和可用的作品链接。同一次确认与同一账号的组合唯一，重复提交同一请求返回原记录。 |
| `cms_distribution_task_log` | 按任务记录素材上传、投稿、结果核对及人工处理的时间、结果来源、平台请求标识、脱敏错误信息。运营可以追溯某次提交经历了哪些步骤。 |

站点从服务端当前上下文取得。绑定、解绑需要站点账号管理权限。分发需同时具备分发操作权限、实际栏目的 `CatalogPrivItem.Publish` 和目标账号使用权。查询、预览与重试也检查对应的数据范围。OAuth 类授权使用一次性、短时有效的 `state` 绑定发起人、站点、应用及回调。服务端换取令牌并在获准时刷新，解绑或撤销后停止用该账号提交。应用密钥从部署端受保护配置读取，账号令牌加密存储，日志与前端响应仅返回授权状态。

预览携带服务端生成的稿件校验值。确认时重新校验来源、状态、账号及校验值，内容有变则要求重新预览。在同一本地事务中按账号保存确认的文本和素材指纹，提交后执行任务，平台网络请求位于事务外。

上传或人工取稿时核对资源归属和文件标识。API 投稿前复核内容仍已发布、允许对外传播、与快照匹配，并检查账号当前授权。人工取稿时同样复核内容，同时检查登记账号在本站已启用、操作人有权使用。条件发生变化时停止交付并显示原因。历史记录保留原快照，站内下线后，已投作品提示编辑到相应平台处理。

### 平台回执怎样显示

| 事实 | 编辑看到的结果与可执行动作 |
| --- | --- |
| 本地已建单，正在读取或上传素材 | 「待提交」或「提交中」，可查看具体目标账号。 |
| 编辑领取头条人工投稿材料 | 显示「待人工投稿」，回填作品链接后标注「人工已确认」并记录操作人。 |
| 平台明确接收并返回稿件标识 | 按回执显示「草稿已创建」「平台已受理」或「审核中」，保存标识。若平台支持查询或通知，按实际证据更新状态。 |
| 确认作品已公开，或平台明确拒绝 | 显示「已公开」并附可用链接，或「已驳回」并给出平台原因。仅有后台人工核对时，单独标明核对人、依据及时间。 |
| 能确认尚未投稿，例如素材校验失败或授权过期 | 显示失败步骤与修复方式。修复后可针对该账号再次提交，其他账号的结果独立保留。 |
| 创建作品的请求发出后超时，平台是否收稿未知 | 显示「待核对」，保留请求标识。先查平台或由有权人员核对账号后台。查到作品就关联原任务，确认未收稿才允许重试。 |

## 实施顺序与验收

| 阶段 | 交付物 | 怎样验收 |
| --- | --- | --- |
| 实施一 · 正常业务流程 | 平台准入核验与开发并行。交付模块装配、账号、单稿预览、按账号建单、抖音普通及分片上传、头条人工投稿、结果查看。头条 API 获准后完成对应适配。 | 从一条视频集选第二条投抖音，核对作品账号和片段。用一篇含分页、封面及配图的文章投头条，逐张核对图片。人工路径验回填与署名，API 路径验真实回执与状态。再覆盖跨站访问、未发布稿、缺失素材及授权过期。 |
| 实施二 · 逐项处理复杂工况 | 以首阶段实际代码列出需解决的问题，如进程在建单后退出、多实例处理同一任务、平台限流、大文件中断、回调重复或乱序。逐项说明影响、方案和验证方式，按评审选定的问题实施。 | 对选定问题注入故障，核对任务历史和平台侧作品数。例如模拟平台已收稿但响应丢失，远端同一作品在 CMS 只关联一次。 |
| 实施三 · 完整审查与测试 | 审查权限、凭据、状态和素材一致性，验证四方言迁移、管理端及 CMS 原发布流程，提供联调结果与未验证项。 | 以真实授权账号和允许公开的测试稿验收。逐账号核对 CMS 记录与平台结果，验证跨站隔离、失败提示及站内发布回归。平台资格、草稿、受理、公开分别列明。 |

首期评审需要确定的是手动分发入口、公开稿件范围和视频集单条投稿规则。平台侧最先验证抖音应用能否取得代发布权限，以及目标头条号能否取得图文投稿资格。这两项直接决定各自可上线的能力。[项目开发原则](../../.codex/rules/development-principles.mdc) · [项目扩展原则](../../.codex/rules/extensibility-principle.mdc)
